The Problem · 问题设定02 / 08

精度落差不是缺陷,
是这个场景的固有约束

目标场景是空地协同:无人机在空中给出目标的粗略位置(米级),小车负责地面的精确执行(厘米级)。

导航能把车送到目标附近,却送不进抓取窗口。这中间缺一层 —— 本项目的核心工作,就是设计这一层。

落差在哪
UAV 位置先验米级
地面导航交付±10 cm
抓取捕获窗口罐子必须落进这个窗口才抓得到 23 × 8 cm
Architecture · 系统架构03 / 08

一条下行通路,一个正交的验证信号

为什么用 structured outputs

LLM 单次调用,plan 字段用 enum 锁死可选动作。Ollama 传 JSON schema,GBNF 约束解码,格式 100% 合法 —— 不加约束时模型会吐散文,json.loads 崩溃。

约束解码只保证格式,不保证语义

用户说一个不存在的地点,enum 会硬塞一个合法但错误的命令 —— 语义校验必须放在下游。

关于那条虚线

Verifier 能返回四种失败原因,但当前流向「中止任务」而非「重新规划」。上行通路未接,是已知缺口,不是遗漏 —— 接上后才构成完整 agentic loop。

硬件 · Jetson · Ubuntu 20.04 · ROS Noetic · RPLidar A1 · 5-DOF 舵机臂 · 麦轮底盘 · 无轮式里程计 最后一条是本项目多数困难的共同源头。

Grounding ★ · 填平鸿沟04 / 08

导航停不准,
不是导航的问题

用一个到达后的闭环对准环,填平 ±10 cm 与 6 cm 之间的鸿沟。

✗ 走过的弯路 — 把导航做准,证伪了

收紧 yaw_goal_tolerance 让车到点转正 → 大角度旋转触发 hector 漂移,纯旋转位置滑了 0.42 m,改回 3.14。

直接把罐当障碍绕 → 矮罐雷达看不见直接撞;高罐被 inflation 挡在外面够不到。这条路上没有解。

关键一问:车的朝向到底需不需要对?
不需要。grab 只关心罐在臂基座系的位置。麦轮 linear.y 纯平移就能把罐送进窗口 —— 不转,就不漂。

Verifier ★ · 物理判据05 / 08

不问模型,问舵机

原来的程序不管抓没抓到,都告诉你「成功了」。抓空是 True,把罐撞飞也是 True —— 上层拿到的成功信号是假的。
改造二 · 物理判据 — 一个舵机读数,三态一刀切开
~63完全张开
~250夹住物体成功捕获,判据落点
~418空夹合到底了,没抓到
不经过视觉链路,也不经过语言模型 —— 相机、提示词、幻觉都骗不了它。错误才是不相关的。
改造前
  • grab / place 永远返回 True
  • 抓空了 = True
  • 把罐撞飞 = True
  • 任务链条无法基于假信号决策
改造后
  • 阻塞返回真实结果
  • 四种失败各自明确 message
  • 舵机读数区间做判据
  • 正交物理量,不再被假 True 骗
硬编码右偏 2 cm

四次全空夹,数值/IK/动作全对。现场肉眼「位置偏右」→ 翻出一个无条件右偏常数,删掉,当天连续成功。

绿色机身误检

底盘与雪碧罐同为绿色,选最大轮廓选中了车自己。屏蔽画面底部 30%,LAB 重标 a=102–116(旧 max 110 切掉半个罐)。

金属罐镜面盲区

正中心镜面反射,深度全 invalid。按半径逐级放大采样窗(r×0.3/0.5/0.7),凑够 ≥20 点取 median ≈ 355 mm。

甜点区 基座前方 0.33–0.38 m 稳定抓取 · >0.40 m 臂长不够 IK 无解 · <0.31 m 伸臂撞翻罐子 抓取基础模块改自团队交接件;本文所述状态返回重构、物理判据标定、逼近环均为本人工作。
